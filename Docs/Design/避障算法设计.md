# 避障算法设计

> M3 controller design for the UGV initial-race long task.

Status: M3 design ready for v1 implementation, 2026-07-08 CST.

## 1. Design Scope

Implementation target:

```text
Models/UGV/Control/ObstacleAvoidanceController/ObsAvoidController_Sysblock2.mo
```

This design only fills the obstacle-avoidance controller output ports:

```text
inputs:  front_dist, rear_dist, left_dist, right_dist
outputs: speed, steer
```

It does not modify official vehicle, road, sensor, scoring, or example systems.
The controller output is an avoidance increment that is blended with the
official path planner by `ControlAllocate.CtrlAlloc` through `factor_oa=0.5` in
the inspected entries. It must not replace path planning authority.

## 3. Controller Strategy

Use a conservative reactive state machine plus continuous steering bias.

State priority:

```text
emergency_front
  -> front_risk
  -> side_risk
  -> cruise
```

State semantics:

| State | Condition | Speed output | Steer output |
|---|---|---|---|
| `emergency_front` | `front_dist < error_side` | reverse or stop bias | steer toward larger side clearance |
| `front_risk` | `front_dist < front_safe` | slow forward bias | steer away from the tighter side |
| `side_risk` | `left_dist < side_safe` or `right_dist < side_safe` | cruise or mild boost | steer toward larger side clearance |
| `cruise` | no risk | `0` avoidance increment | `0` avoidance increment |

Rationale:

- In cruise, output zero increments so the official path planner remains the
  dominant controller.
- During side risk, steer away from the closer side wall or obstacle without
  adding unnecessary speed penalty.
- During front risk, reduce speed and generate stronger steering because the
  front sensor is the highest collision predictor.
- During emergency, apply the existing `speed_error` and `steer_error`
  parameters, but keep outputs bounded to avoid destabilizing the path/PID
  chain.

## 4. v1 Equations

Compute clearance difference:

```text
side_delta = left_dist - right_dist
```

Sign convention:

- `side_delta > 0`: left side has more clearance than right side, steer left.
- `side_delta < 0`: right side has more clearance than left side, steer right.

Bounded steering command:

```text
steer_bias = clamp(k_steer_side * side_delta, -steer_error, steer_error)
```

For front risk, add a front-distance gain:

```text
front_push = clamp(k_rep_front * (front_safe - front_dist), 0, steer_error)
steer = clamp(steer_bias + sign_or_clearance(side_delta) * front_push,
              -steer_error, steer_error)
```

For side-only risk:

```text
side_push = clamp(k_rep_side * (side_safe - min(left_dist, right_dist)),
                 0, steer_error)
steer = clamp(steer_bias + sign_or_clearance(side_delta) * side_push,
              -steer_error, steer_error)
```

For v1 implementation in plain Modelica, use explicit `if` branches and local
intermediate variables instead of introducing external dependencies.

## 5. Parameters

Use existing parameters first:

| Parameter | Initial value | Role |
|---|---:|---|
| `speed_Cruise` | 1.0 | Upper reference for mild avoidance speed increment. |
| `front_safe` | 1.0 | Front risk threshold. |
| `side_safe` | 0.3 | Side risk threshold. |
| `k_rep_front` | 2.0 | Front repulsion gain. |
| `k_rep_side` | 1.0 | Side repulsion gain. |
| `k_steer` | 0.6 | Reserved front/combined steering gain. |
| `speed_avoid_front` | 0.5 | Slow-forward increment under front risk. |
| `speed_avoid_side` | 1.5 | Mild side-risk speed increment. |
| `speed_error` | -0.8 | Emergency reverse/stop increment. |
| `k_steer_side` | 3.0 | Side clearance steering gain. |
| `steer_error` | 0.8 | Steering saturation. |
| `error_side` | 0.15 | Emergency front/side threshold. |

Do not tune these globally before M4 can load/check/simulate. M5 should tune
only after one reproducible run is available.

## 6. Implementation Constraints

1. Edit only `ObsAvoidController_Sysblock2.mo` for M4.
2. Do not modify official examples, tracks, vehicle, road, sensors, or scoring.
3. Keep the controller explainable and code-generation-friendly.
4. Avoid division by distance in v1; sensor values can be small and the current
   parameters already provide bounded linear gains.
5. Keep outputs saturated:

```text
speed in [speed_error, speed_avoid_side]
steer in [-steer_error, steer_error]
```

## 7. M4 Verification Gate

After implementation:

1. Run `CheckModel("UGV.Example.Race1")`.
2. Run a bounded `SimulateModel` gate equivalent to M2 first.
3. Read `T`, `cR`, `cO`, and `P`.
4. If check or simulation fails, record blocker evidence and inspect local
   source before tuning.
5. If bounded gate passes, proceed to M5 one-track tuning.

## 8. Open Risks

- The sign convention of `steer` is inferred from control routing and must be
  validated by simulation. If side avoidance worsens collisions, M5 should try
  a single sign flip as a controlled experiment and record both runs.
- M2 used `Race1` with finite `stopTime=12`; it does not prove full route
  completion or official four-track behavior.
- Current implementation is equation-bridge evidence, not a polished graphical
  Sysblock layout claim.
